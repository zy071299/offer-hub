# 接口文档（二）：题目模块

本文档列出题目模块的完整接口。所有接口的通用规范（响应格式、错误码、鉴权方式）见接口文档（一）。

题目模块的接口分为两类：题目查询接口使用软鉴权，游客和登录用户都能访问；标记掌握状态的接口使用强制鉴权，必须登录。

## GET /api/v1/question/all/list 题库全量列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`job_name`|string|否|职位方向过滤，如后端开发、前端开发、AI开发|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "job_name": "后端开发",
      "series_list": [
        {
          "series_id": "s001",
          "series_name": "数据库",
          "order": 1,
          "bank_list": [
            {
              "bank_id": "b001",
              "bank_name": "MySQL题库",
              "bank_logo": "https://example.com/mysql.png",
              "desc": "MySQL核心知识点",
              "count": 120,
              "order": 1
            }
          ]
        }
      ]
    }
  ]
}
```

返回结构按职位方向分组，每个方向下包含系列列表，每个系列下包含题库列表。`count` 是该题库下的题目数量。

## GET /api/v1/question/list 题目列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`bank_id`|string|否|题库 ID 过滤|
|`keyword`|string|否|关键词搜索，匹配标题和内容|
|`difficulty`|int|否|难度过滤：1简单 / 2中等 / 3困难|
|`tags`|\[\]string|否|标签过滤，支持多个|
|`job_name`|string|否|职位方向过滤|
|`user_tag`|int|否|掌握状态过滤：1已掌握 / 2晚点再刷 / 3未掌握，需要登录|
|`sort_by`|string|否|排序字段：create\_time / view\_count / thumbs\_up\_count / dislike\_count|
|`sort_order`|string|否|排序方向：asc / desc|
|`page`|int|否|页码，默认 1|
|`page_size`|int|否|每页数量，默认 20|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "total": 100,
    "list": [
      {
        "question_id": "q001",
        "bank_list": ["b001", "b002"],
        "title": "什么是 Redis 的持久化机制？",
        "content": "Redis 提供了两种持久化方式...",
        "difficulty": 2,
        "tags": ["Redis", "数据库"],
        "status": 1,
        "vip": false,
        "hot_degree": 85,
        "view_count": 1024,
        "thumbs_up_count": 256,
        "dislike_count": 12,
        "order": 1,
        "user_tag": 0,
        "user_liked": false,
        "create_time": "2024-01-01 12:00:00",
        "update_time": "2024-01-01 12:00:00"
      }
    ]
  }
}
```

游客访问时，每条题目的 `content` 截断至前150字。`user_tag` 和 `user_liked` 返回零值。

登录用户返回完整内容，`user_tag` 和 `user_liked` 反映当前用户的实际状态。

`user_tag` 过滤参数只对登录用户有效，游客传入该参数会被忽略。

## GET /api/v1/question/meta/list 题目元数据列表

**鉴权**：软鉴权

**请求参数**：与 `/api/v1/question/list` 相同，支持全部过滤和排序参数。

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "total": 100,
    "list": [
      {
        "question_id": "q001",
        "title": "什么是 Redis 的持久化机制？"
      }
    ]
  }
}
```

只返回题目 ID 和标题，用于题目导航侧边栏。不包含内容字段，响应体积小。

## GET /api/v1/question/detail 题目详情

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`question_id`|string|是|题目 ID|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "question_id": "q001",
    "bank_list": ["b001"],
    "title": "什么是 Redis 的持久化机制？",
    "content": "Redis 提供了两种持久化方式...",
    "difficulty": 2,
    "tags": ["Redis", "数据库"],
    "status": 1,
    "vip": false,
    "hot_degree": 85,
    "view_count": 1024,
    "thumbs_up_count": 256,
    "dislike_count": 12,
    "order": 1,
    "user_tag": 1,
    "user_liked": true,
    "create_time": "2024-01-01 12:00:00",
    "update_time": "2024-01-01 12:00:00"
  }
}
```

游客访问时，`content` 截断至前150字。登录用户返回完整内容，并附加 `user_liked` 和 `user_tag` 的实际值。

## GET /api/v1/question/hot/list 热门题目列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`limit`|int|否|返回数量，默认 10|
|`job_name`|string|否|职位方向过滤|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [
      {
        "question_id": "q001",
        "bank_list": ["b001"],
        "title": "什么是 Redis 的持久化机制？",
        "view_count": 1024
      }
    ]
  }
}
```

按 `hot_degree` 降序排列，只返回 ID、标题和浏览数，用于首页和热门题目页展示。

## POST /api/v1/safe/tag\_question 标记题目掌握状态

**鉴权**：强制登录

**请求体**：

```JSON
{
  "question_id": "q001",
  "tag": 1
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`question_id`|string|是|题目 ID|
|`tag`|int|是|掌握状态：0未标记 / 1已掌握 / 2晚点再刷 / 3未掌握|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": null
}
```

对同一题目重复标记时执行 upsert，更新已有记录。传入 `tag: 0` 表示取消标记。
