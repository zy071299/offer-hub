# 接口文档（一）：规范与认证模块

本文档定义接口通用规范，并列出认证模块和用户信息模块的完整接口。

## 通用规范

### 响应格式

所有接口统一返回以下 JSON 结构，HTTP 状态码始终为 0：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

`code` 为 0 表示成功，非 0 表示失败。`msg` 是人类可读的描述。`data` 是业务数据，失败时为 `null`。

### 错误码

|code|含义|
|---|---|
|`0`|成功|
|`400`|参数错误|
|`401`|未认证（token 无效或已过期）|
|`403`|无权限|
|`500`|服务器内部错误|

### 认证方式

需要登录的接口，在请求头中携带 JWT token：

```Plaintext
Authorization: Bearer <token>
```

### 鉴权模式

项目有两种鉴权模式：

- **强制鉴权**：没有有效 token 直接返回 401，用于必须登录才能操作的接口，比如发表评论、点赞。

- **软鉴权**：有 token 就解析用户信息，没有 token 也放行。用于游客和登录用户都能访问、但返回数据不同的接口，比如题目详情。游客访问时 `content` 截断至前150字，`analysis_content` 置空；登录用户返回完整内容，并附加 `user_liked`、`user_tag` 字段。

## 认证模块

### POST /auth/register 注册

**鉴权**：无需登录

**请求体**：

```JSON
{
  "username": "testuser",
  "password": "123456"
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`username`|string|是|用户名，最长50字符，不能为空|
|`password`|string|是|密码，最少6位|

**响应**：

```JSON
{
  "code": 0,
  "msg": "注册成功",
  "data": null
}
```

**错误情况**：用户名已存在返回 `code: 500, msg: "用户名已存在"`；参数不合法返回 `code: 500, msg: "用户名或密码不符合要求"`。

### POST /auth/login 登录

**鉴权**：无需登录

**请求体**：

```JSON
{
  "username": "testuser",
  "password": "123456"
}
```

**响应**：

```JSON
{
  "code": 0,
  "msg": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userInfo": {
      "userId": "abc123",
      "username": "testuser",
      "nickName": "测试用户",
      "avatar": "https://example.com/avatar.jpg",
      "sex": 1,
      "vip": false,
      "phone": "",
      "email": "",
      "userStatus": 1,
      "userType": 1
    }
  }
}
```

注意 `userInfo` 字段使用 camelCase 命名，与其他接口的 snake\_case 不同。

### POST /auth/logout 登出

**鉴权**：强制登录

**请求头**：`Authorization: Bearer <token>`

**请求体**：无

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "message": "登出成功"
  }
}
```

登出后 token 写入 Redis 黑名单，TTL 等于 token 剩余有效期。黑名单中的 token 再次请求会返回 401。
